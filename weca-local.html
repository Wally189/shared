WECA Local Discovery

Before Copilot tells somebody how WECA “does things”, it should build the current local picture from public authoritative sources and label what it still does not know. Only then should it interpret an internal tracker, procedure or inherited habit supplied through an approved workplace route.

This is not an official WECA procedure. It is an independent public-source discovery method. Public information can reveal the formal governance surface; it cannot reveal every current internal workflow, tracker, clearance convention or Microsoft 365 implementation.

The evidence labels

LabelMeaning
PUBLICLY VERIFIEDCurrent proposition supported by an official WECA/ModernGov/legislation source.
LOCAL-USER-SUPPLIEDInformation or document supplied through a permitted workplace route. Useful locally; not suitable for publication merely because Copilot has seen it.
LOCAL-UNVERIFIEDAcronym, habit, tracker or claim whose exact current function/authority has not yet been established.
INFERENCEA reasoned hypothesis. Must be tested before it becomes process design.

Public WECA discovery order

  1. Official democracy / transparency page. Identify the public description of meetings, decisions, forward work and transparency.
  2. Current constitution. Follow the official Constitution page to the current ModernGov constitution and record version/currentness before relying on it.
  3. Current bodies. Reconstruct Combined Authority / Joint Committee / Overview & Scrutiny / Audit and any current successor/additional bodies from current official records.
  4. Forward work. Inspect the current forward plan / issue history: decision type, proposed decision-maker, publication/decision timing and related documents.
  5. Officer / delegated decisions. Inspect current ModernGov officer decision records and published decision notices.
  6. Published assurance / accounts / frameworks. Use these to discover control structures and historic statements about internal processes, but label their date. Do not silently treat a 2023 description as the 2026 process.
  7. National-local cross-check. Use the Governance Localiser to check that the local process fits current legislation/orders and the current constitution.

What is publicly established today

Publicly verified WECA's public democracy page identifies meetings/decisions and a forward plan as parts of its decision-making transparency. The official Constitution page points users to the constitution on ModernGov. Current ModernGov records publish officer/delegated decisions with decision-maker, status, key-decision status, decision/publication dates and accompanying documents.

Publicly verified Published 2026 records explicitly use the term Officer Decision Notice. Therefore ODN may be expanded to Officer Decision Notice when the source/context is WECA officer decisions.

Historic public evidence The authority's published 2022/23 accounts said an intranet page gave officers information about the stages for formal and urgent decision-making. That is useful evidence that an internal process/guidance layer existed at that time; it is not proof of the exact 2026 intranet content.

Local-unverified This public review does not establish a WECA-specific meaning or authoritative process for an “ODP tracker”. Do not guess. Ask the operator what it stands for, what it records, who updates it and what outcome depends on it, or inspect a permitted current example.

The questions Dave must ask about an ODP/ODN tracker

  • What does the acronym mean here?
  • What is the tracker for: pipeline, clearance, publication, decision record, action follow-up, or several things?
  • Which fields are mandatory because of law/constitution/process, and which exist because “we've always had that column”?
  • Who creates a row, who updates it, who relies on it and who closes it?
  • What event starts the process? What event proves completion?
  • Where is the canonical decision once complete?
  • What is copied manually into/from ModernGov, emails, Word forms or another spreadsheet?
  • What colours/free-text codes have hidden meaning?
  • Are there linked workbooks, queries, formulas or downstream reports?
  • What fails if the tracker is unavailable?
  • What current local instruction authorises the workflow?

Then find the least disruptive option

OPTION A — REPAIR
Keep the current tracker; remove defects, standardise fields, document ownership.

OPTION B — CONSOLIDATE
Keep Excel/Microsoft 365 but remove duplicate trackers or manual re-entry.

OPTION C — STRUCTURE
Move shared finite state into an appropriate List/library/workflow while preserving familiar views.

OPTION D — INTEGRATE / AUTOMATE
Only after the process is stable: use Power Query, supported connectors, rules or controlled automation to reduce deterministic re-keying.

The test is not “is SharePoint newer?” It is “does this remove real duplication/risk while preserving authority, history and usability?”

People: gentle without games

Do not label a colleague insecure, technophobic or obstructive. Record only observable barriers: uncertainty, skill/confidence, workload, process knowledge, stated objection, dependency or loss of a familiar control. A sceptical experienced colleague should be asked to identify edge cases the proposed change might break.

The adoption sequence is: show the existing problem → preserve the useful control → prototype beside it → let the user break it → prove the outcome → write the plain-English SOP → retire the duplicate only when safe.

WECA Local Discovery prompt

GOAL: Build the current public WECA Democratic Services/process baseline for [topic] before advising me.
SOURCES: Current official WECA website, current ModernGov constitution/meetings/forward-plan/officer-decision records, legislation and current official guidance.
CLASSIFY: PUBLICLY VERIFIED / LOCAL-USER-SUPPLIED / LOCAL-UNVERIFIED / INFERENCE.
DO NOT: infer internal acronyms, publish internal material, or assume an old public document describes the current internal process.
THEN: compare the public baseline with the local tracker/process I describe or am permitted to attach.
OUTPUT:
1. Public source map
2. Formal body/decision/process map
3. What is genuinely known about the local artefact
4. Unknowns/questions
5. Duplication and hidden controls
6. No more than 3 improvement options
7. One reversible next step
8. Plain-English SOP for the step
9. Progress Block for OneNote
STOP after the one next step unless I ask for the full roadmap.
