OneDrive for working space; SharePoint for shared knowledge and state

Microsoft 365

The reference Microsoft 365 architecture separates personal working space, shared team knowledge, structured state, calculation and the organisation's existing canonical systems. It is a destination, not an excuse to recreate every existing spreadsheet in a shinier product.

Legacy first. Before creating a List or library, inventory the current spreadsheets, folders, colour conventions, formulas, linked files, owners and unofficial workarounds. If a neon cell or red comment carries operational meaning, capture that meaning before removing the formatting. See Quiet modernisation and the Legacy System Inventory.

Design fields, not coloured cells

Microsoft Lists and SharePoint support typed columns, required values, controlled choices and validation. Use those controls when the information has a defined meaning. A status such as Waiting for legal clearance belongs in a Status/Dependency field; it should not exist only as red text typed into a comments box.

If the information is…PreferAvoid as the primary control
A fixed statusChoice columnFree text such as “DONE!!!” or coloured wording
A person responsiblePerson fieldInitials buried in notes
A due dateDate fieldA date typed into narrative text
Yes/noYes/No fieldY, Yes, yep, tick, colour
Long explanationMultiline textForcing narrative into a coded status field

Vendor guidance Microsoft documents required fields, Choice columns and validation for consistent entries. Formatting can then highlight a structured status without changing the underlying data.

Colour is presentation, not data

Colours have no gender in this architecture. Use colour only when it has a defined functional purpose, uses an accessible palette and is accompanied by a text label or other cue. Pink, purple, yellow or red are not intrinsically wrong; arbitrary decoration and colour-only meaning are the problem. WCAG 2.2 explicitly says colour must not be the only way information is conveyed.

Excel

Use for calculations, analysis, models and exploration. Do not make a multi-user spreadsheet canonical simply because everybody knows how to colour cells. Before retiring an existing workbook, check formulas, macros, linked workbooks, hidden sheets, filters, recurring copy/paste steps and downstream users.

Filenames and versions

Use different rules for different contexts. Personal working files can benefit from a date and clear purpose. Shared canonical documents should normally have a stable descriptive name and use SharePoint/OneDrive version history and metadata instead of proliferating names such as FINAL_v7_REALLYFINAL_23Sep.docx. Microsoft 365 version history can track and restore earlier versions when configured.
