Engine support layer

The ten engines do not need a new platform. They need a common handoff format, a truthful view of the available Microsoft environment, one lightweight verification gate and simple instructions for moving between AI advice and ordinary workplace tools.

0 — Set up the operator before redesigning the service

For broad modernisation, the first job is to make the current operator reliable, repeatable and increasingly independent—not to announce a transformation programme. Establish a private working profile in the approved OneNote log or equivalent. Do not publish it on this website.

Record only what is useful for work: role and scope; recurring duties; important cycles and deadlines; key professional interfaces; authoritative systems; known tool constraints; preferred working/output style; current pain points; skills being learned; and the evidence needed to show reliable delivery and useful improvement.

Professional-evidence rule: quietly capture outcomes such as deadlines protected, errors prevented, risks identified early, handovers improved, duplicated effort removed and methods made easier for others to use. Prefer useful work and reproducible evidence to conspicuous self-promotion. When a personal method proves useful, turn it into a neutral repeatable method that another competent colleague could use.

The profile is a working aid, not a personnel record. Do not copy sensitive personal information, informal judgements about colleagues or confidential employer material into an AI prompt merely to personalise the coach.

2 — Microsoft 365 Capability Registry

A product name is not a capability. Licensing, tenant configuration, client version, permissions, file location, authentication and organisational policy can all change what is actually usable. Therefore every material tool assumption starts as UNKNOWN until checked in the real environment.

StateMeaning
AVAILABLEObserved or authoritatively confirmed for the required use in this environment.
LIMITEDAvailable, but a material client, permission, refresh, policy, data or workflow constraint applies.
NOT AVAILABLEConfirmed unavailable or not permitted for the required use.
UNKNOWNNot yet checked. Do not design a dependency around it.

Each capability entry records: capability; state; client/environment; permissions; dependencies; approved data/location constraints; authoritative source or observed test; last verified date; and the smallest next test if unresolved.

The starter registry includes Excel desktop/web, workbook links, Power Query, OneDrive, SharePoint, Lists, OneNote, classic/new Outlook, shared mailboxes, Teams, Power Automate and Copilot. It deliberately makes no assumption that any of them are present merely because an organisation says it uses Microsoft 365.

3 — Verification Gate

Use the gate whenever more than one engine contributes to a material output, or whenever an engine output is about to cause a real process, record, deadline, communication or tool change.

  1. Source: are material claims traceable to the underlying evidence?
  2. Authority: have national rule, local rule, local practice and professional judgement been kept distinct?
  3. Capability: is every required tool capability AVAILABLE or explicitly LIMITED with an accepted workaround?
  4. Privacy / records: is the proposed information handling permitted and proportionate?
  5. Commitments: are owners, deadlines, escalation routes and assurances evidenced rather than invented?
  6. Change safety: is the smallest step reversible, and is the control performed by the existing workaround understood?
  7. Consistency: do engine outputs contradict one another or the Case Bus?
  8. Professional boundary: does Legal, Monitoring Officer, Finance/S151, DPO/IG, IT/security or another competent role need to answer?
  9. Evidence: what result will prove the step worked?

Return only PASS, PASS WITH LIMITS or STOP / REFER, followed by the material limitations or referral. This is a release gate, not a score.

4 — Human tool adapters

An adapter is simply the instruction that translates an engine recommendation into a safe human action in the tool actually available. No API, backend or automation platform is required.

Excel / Power Query

Before: identify the authoritative workbook, make a safe copy where appropriate, record links/queries/macros/named ranges and check the capability registry. Do: test one bounded change with dummy or permitted data. Return: what changed, refresh/result, error text and rollback position. Stop: if ownership, refresh credentials, downstream dependency or data sensitivity is unclear.

Outlook / shared mailboxes

Before: confirm mailbox type, owner, permissions, retention/archive position and business purpose. Do: inventory first; make one reversible rule/folder/process test only after constraints are understood. Return: observed behaviour and effect on missed actions/retrieval effort. Stop: before bulk deletion, retention change, uncontrolled copying or AI processing of sensitive historic mail.

OneNote

Use: as the operator's working continuity layer where organisational policy permits. Keep the latest Progress Block in 00 Current State; store capability observations and experiment notes in their relevant sections. Do not: turn OneNote into the authoritative home for formal decisions, records or confidential material that belongs elsewhere.

OneDrive / SharePoint / Lists

Before: identify the authoritative current home and permissions. Do: use OneDrive for personal work in progress; shared libraries/Lists only where approved and demonstrably better for shared state. Return: location, ownership, version/metadata behaviour and retrieval result. Stop: before duplicating canonical records merely to make a new structure look complete.

Copilot / AI

Before: provide the current Progress Block, the relevant Case Bus and only permitted evidence. Do: route to the smallest useful engine combination. Return: source-linked findings, verification state, one next action and an updated Progress Block. Stop: when the bounded step is complete or a competent professional must answer.

5 — State between sessions

At the start of a continuing session, read the latest Progress Block first. Then load only the Case Bus and capability entries relevant to the current step. At the end, return one replacement Progress Block. Do not reconstruct the whole modernisation story from memory every time.

The Case Bus carries the bounded case; the Progress Block carries continuity; the organisation's real systems remain authoritative.

6 — What this layer deliberately is not

  • not a backend, queue, message broker or database;
  • not a Power Automate dependency;
  • not an API integration layer;
  • not a new source of organisational truth;
  • not permission to upload workplace data to a public site or unapproved AI;
  • not an excuse to create a new engine for every task name.

Scale rule: prove the method personally → make it repeatable → document the smallest neutral SOP → let another person test it → only then consider a shared-tool or automation change.
