Excel

Use for calculations, analysis, models and exploration. A spreadsheet does not become bad merely because it is old or visually eccentric. First establish whether it is a register, workflow tracker, calculation model, reporting view, temporary analysis or duplicate/shadow record. Then decide whether to KEEP, CLEAN, CONSTRAIN, MIGRATE or RETIRE it.

Where Excel remains appropriate, improve data quality before replacing the tool. Microsoft supports data validation and drop-down lists to restrict entries and provide input/error guidance. Status, owner category, committee name and similar controlled concepts should not be unrestricted free text unless there is a genuine reason.

Use the Spreadsheet Triage template.

Colour is presentation, not data

Do not encode essential meaning only through highlight colour, font colour or decorative schemes. WCAG 2.2 explicitly requires that colour is not the only visual means of conveying information. Replace “red text means late” with an explicit Status = Overdue value and, if useful, let conditional formatting show red as a secondary cue. Use a small neutral visual system with colours assigned to stable functions rather than people, preferences or history.

Bright or familiar formatting need not be stripped out on day one. First make the underlying meaning explicit; then simplify the presentation once staff no longer depend on the colour as memory.

Structured fields before new platforms

Microsoft Lists Choice columns are designed to keep stored values consistent, and Lookup columns can constrain values to an existing source list. A useful migration often begins by defining controlled vocabularies in the old workbook, proving them with users, and only then moving the same information model into a List.

File naming

Use boring, recognisable names. For working files, a starting pattern is:

YYYY-MM-DD - Body or workstream - Subject - Record type

Add a short status/version suffix only where the storage system does not already provide reliable version history. Avoid “FINAL v2 FINAL USE THIS ONE”. In SharePoint, prefer metadata and version history over encoding every attribute into filenames.

Metadata

Body ID · record type · meeting date · decision date · subject · owner role · status · authority/power · publication class · retention class · effective from · review date · source status · predecessor · successor · version status.
