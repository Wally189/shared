Maturity & measurement

A service can use old software and be well controlled; it can use brand-new software and still depend on folklore. Assess the service, not individual staff, and move level only when evidence shows the underlying capability has improved.

Maturity continuum

LevelWhat it looks likeEvidence needed to move on
0 — Functional / heroicWork gets done, but important meaning sits in people, inboxes, colours, filenames and duplicated trackers.Inventory of critical processes, systems, bodies, mailboxes and key-person dependencies.
1 — MappedOwners, purposes, authoritative sources and undocumented workarounds are known.Critical artefacts classified; risks/unknowns visible; do-not-change items recorded.
2 — ControlledCore templates, naming, deadlines, source rules and handovers are consistent enough to reproduce.Fewer corrections; consistent statuses; documented fallback/rollback; new starter can follow core tasks.
3 — StructuredFinite data becomes real fields; shared state moves out of uncontrolled free text; records have known homes.Reduced duplicate entry; improved retrieval; clear data ownership; no loss of historical meaning.
4 — IntegratedOne canonical record supports multiple useful views; dependencies and forward work are visible across processes.Fewer parallel trackers; handoffs work; stale copies decline; routine cross-process questions are answerable.
5 — AssuredQuality checks, accessibility, regression tests, metrics and controlled automation catch problems before they become meeting-day crises.Measured reliability/quality trend; defects produce corrective action; automation has monitoring/rollback.
6 — Exemplary / adaptiveThe service is easy to learn, resilient to absence, evidence-led, transparent and able to improve without creating a new bureaucracy each time.Sustained outcomes, periodic effectiveness review, continuous learning and no critical capability dependent on one person's memory.

How Dave should use this

1. Baseline only the current service dimensions relevant to the problem.
2. Record evidence, not impressions.
3. Pick one gap whose improvement removes real friction or risk.
4. Define one primary measure and one do-not-harm measure.
5. Run the baby-step test.
6. Compare before/after.
7. Keep, change, roll back or retire.
8. Reassess maturity only when evidence changes.

Do not use maturity levels to rank staff, departments or political actors. This is a process/capability tool. HM Treasury's 2026 Orange Book explicitly notes that maturity models can support structured assessment and targeted improvement; GovS 002 similarly provides a continuous-improvement assessment framework for project delivery.

Independent and unofficial. Maturity levels are a proposed improvement model, not a statutory or professional grading scheme.
