One small, reversible improvement at a time

Baby-step roadmap

Modernise in increments small enough to reverse, test and explain. The working legacy system is the baseline, not the enemy.

The legacy-to-modern transition method explains the human and behavioural side of this roadmap.

0 — Public research

Build the source model. No workplace change.

1 — Observe before tidying

Map how work really happens: spreadsheets, colour conventions, personal folders, manual workarounds, duplicate trackers, recurring emails and undocumented hand-offs. Record what each artefact achieves before changing it. A visually messy tool may encode tacit rules that are not documented anywhere else.

2 — Personal learning and low-risk fixes

Understand bodies, decision routes and recurring business. Improve only personal working practices or public-material tasks permitted by local policy. Examples: clearer file names, a private checklist, a validated calculation, or a better research note.

3 — Historical public-document testing

Test Context Builder, Research and Paper Readiness against published material with known outcomes.

4 — Stabilise one live process

Choose one recurring irritation. Define the current process, owner, inputs and output. Fix ambiguity before changing platforms: standard names, explicit status values, defined owners and dates, and a known canonical record.

5 — Constrain bad data gently

Where the existing tool remains adequate, improve it in place first. Replace free-text status fields with controlled choices or Excel data validation; make dates real date fields; add short input guidance; use colour only as a secondary cue. This produces value without asking staff to learn a new system.

6 — Team-visible optional method

Share the useful checklist, template or cleaner tracker. Lead with the solved irritation rather than the technology. Keep the old route available during a bounded trial and specify the test for retiring it.

7 — Shared structured knowledge

When the information model is proven, move suitable shared state into Lists/SharePoint or the existing specialist system. Migrate deliberately, preserve provenance, and avoid permanent parallel truth.

8 — Controlled automation

Automate only stable deterministic steps: reminders, status changes, recurring-date calculations and notifications. Make failure, ownership and rollback visible.

9 — Broader operating model

Only after several small changes show measurable benefit should the wider service model be reconsidered. The argument for change should increasingly be “this is easier and more reliable”, not “this is more modern”.

Transferable practice
The GOV.UK Service Standard emphasises user needs, whole problems, simplicity, iteration, privacy, success measures and suitable technology. Those disciplines transfer without pretending Democratic Services is itself a GOV.UK transaction.
